# 教材规范条目溯源索引

> 溯源对象：《Verilog 数字系统设计教程（第 4 版）》夏宇闻 编著，清华大学出版社。
> 本文只做**索引与对照**：给出规则原文摘要 + 书页号 + 本规范（`SKILL.md` / `references/`）中对应的条款编号，
> 并客观标注教材中已过时或与现代实践冲突之处。教材原文版权归原作者及出版方所有，此处仅作规范溯源引用。

## 本篇速览

1. 教材的规范核心是**四份编号清单**：p.380「语汇代码的编写标准」8 条、p.380-381「可综合代码的编写标准」15 条、p.180-181「13.3 综合的一般原则」4 条 +「13.4 语言指导原则」8 条、p.197「14.2 Verilog 模块编程要点」8 条。本规范的铁律 A~I 几乎全部可以回溯到这四份清单。
2. 教材的**总纲只有一句**：p.166「只要按照一定的原则来编写代码就可以保证 Verilog 模块综合前和综合后仿真的一致性」。所有条款的存在理由都是这一句——不是"综合不出来"，而是"综合出来了但和仿真不是一回事"。
3. 教材真正过时的地方**只有写法，不是道理**：敏感表手工列全（`always @*` 更安全）、非 ANSI 端口、`casex`、片内三态总线、`always @(posedge write)` 拿数据信号当时钟、异步复位没讲同步释放。
4. 有两处教材**自己前后不一致**，本规范必须选边：`case` 的 `default` 赋 `'bx`（p.177）还是回安全态（p.171）；单 always 块状态机（p.169）还是多 always 块（p.173，Synopsys 推荐）。
5. 引用教材页码时**必须区分 p.380 上的两份清单**（语汇/可综合都从 (1) 开始编号），否则 "p.380 (2)" 会同时指向两条完全不同的规则——见文末「与主规范的冲突」。

## 0. 如何使用本索引

- **页码基准**：全部为**书上印刷页码**。调研原始文件用的是 PDF 页码，换算关系 `书页 = PDF 页 − 15`（例：书 p.380 = PDF p0395）。
- **来源标签**：本文所有条目都是 `[教材]`，故只在需要对照时才额外标注 `[业界]` / `[工具]`。
- **适用范围标签**：`[通用]` `[FPGA]` `[ASIC]` `[V2001]` `[SV]`。教材成书基线是 **IEEE 1364-1995**（p.376 明确以此为准），但第 6 章 p.80-81 已经收录了 Verilog-2001 的 `@*` / `@(*)` 与逗号敏感表——所以"教材=纯 1995"这个印象并不准确，详见 §8.1。
- **条款编号**：指 `SKILL.md` §1 铁律中的 `A1`…`I`，或 `references/NN-*.md` 文件。

## 1. p.380「语汇代码的编写标准」8 条（原文全录）

面向**人**的标准——原书 p.379 说它"规定了文本布局、命名和注释的约定，其目的是为了提高源代码的可读性和可维护性"。

| # | 原文摘要（p.380） | 本规范条款 | 范围 |
|---|---|---|---|
| 语汇(1) | 每一个 Verilog 源文件中只准编写一个模块，也不要把一个模块分成几部分或写在几个源文件中 | `A1` | `[通用]` |
| 语汇(2) | 源文件的名字应与文件内容有关，最好一致（例 `ModuleName.v`） | `A2` | `[通用]` |
| 语汇(3) | 每行只写一个声明语句或说明 | `A4` | `[通用]` |
| 语汇(4) | 用一层层缩进的格式来写 | `A4`（本规范固化为 4 空格、禁 Tab） | `[通用]` |
| 语汇(5) | 用户定义变量名的大小写应自始至终一致 | `B4` | `[通用]` |
| 语汇(6) | 用户定义变量名应该是有意义的，而且含有一定的有关信息。而局部变量名（例如循环变量）可以是简单扼要的 | `B3` | `[通用]` |
| 语汇(7) | 通过注释对源代码作必要的说明；**没有必要把源代码已能说明的再注释一遍**，而对接口（模块参数、端口、任务、函数变量）做必要的注释很重要 | `A5`、`references/01` | `[通用]` |
| 语汇(8) | 尽可能多地使用参数和宏定义，而不要在源代码的语句中直接使用字母、数字和字符串 | `B5` | `[通用]` |

**为什么值得当回事**：语汇(1)(2) 不是洁癖——综合器、lint 与仿真器都靠"文件—模块"映射做增量编译与错误定位；一个文件塞两个模块，Verilator 的 `DECLFILENAME` 会直接告警 `[工具]`，更实际的后果是 `` `include `` / 编译列表一乱，你说不清综合器读进去的到底是哪份代码。语汇(7) 是 `A5` 的直接依据，也是本规范**不要求逐行注释**的依据（原话就是"没有必要把已能说明的再注释一遍"），注释预算要花在接口契约上。语汇(8) 与 `B5` 一致，但本规范把"宏定义"收窄为 `parameter`/`localparam`：教材年代 `` `define `` 是常用手段（p.178 `` `define state1 2'h1 ``、p.182 `` `define plus 3'd0 ``），而宏**全局无作用域**，多文件工程里会互相污染。

## 2. p.380-381「可综合代码的编写标准」15 条（原文全录）

面向**工具**的标准——p.379 说其目的是"避免常见的不能综合和综合结果存在缺陷的问题"。**这 15 条是整本书的规范骨架**，本规范铁律 C/D/E/F/G/H 基本是它的展开。

| # | 原文摘要（p.380-381） | 本规范条款 | 范围 |
|---|---|---|---|
| 可综合(1) | 把设计分割成较小的功能块，每一块用行为风格去设计。除对速度响应要求比较临界的部分外，都应避免使用门级描述 | `H2` | `[通用]` |
| 可综合(2) | 建立定义得很好的时钟策略并在源代码中清晰体现；**保证时钟和复位信号是干净的（即不是由组合逻辑或没有考虑到的门产生的）** | `E1`、`E5`、`references/06` | `[通用]` |
| 可综合(3) | 建立定义得很好的**测试（制造）策略**：使所有触发器都是可复位的、测试能通过外部引脚进行、没有冗余的功能 | `E3` + `E7`（DFT） | `[ASIC]` 强 / `[FPGA]` 弱 |
| 可综合(4) | 每个源代码都必须遵守并符合在 Always 声明语句中介绍过的**某一种可综合标准模板** | `assets/templates/`；模板原文见 p.382-383 | `[通用]` |
| 可综合(5) | 描述组合和锁存逻辑的 always 块，**必须在块开头的控制事件列表中列出所有的输入信号** | `C2`（本规范用 `always @(*)` / `always_comb` 等价实现） | `[通用]` |
| 可综合(6) | 描述组合逻辑的 always 块**一定不能有不完全赋值**，所有输出变量必须被各输入值的组合值赋值，不能有例外 | `C3`、`C4` | `[通用]` |
| 可综合(7) | 描述组合和锁存逻辑的 always 块**一定不能包含反馈**：块中已被定义为输出的寄存器变量绝对不能再在该块中读进来作为输入 | `C5` | `[通用]` |
| 可综合(8) | 时钟沿触发的 always 块**必须是单时钟的**，且任何异步控制输入（通常是复位或置位）必须在控制事件列表中列出 | `D4`、`E2` | `[通用]` |
| 可综合(9) | **避免生成不想要的锁存器**：无时钟 always 块中，输出变量被赋予某个未列入电平敏感控制事件的信号值，会在综合中生成不想要的锁存器 | `C2`、`C3` | `[通用]` |
| 可综合(10) | **避免不想要的触发器**：时钟沿触发的 always 块中用非阻塞赋值对 reg 赋值会生成触发器；寄存器变量在该块中经多次循环其值仍保持不变，综合后也会生成触发器 | `references/03`、`references/07` | `[通用]` |
| 可综合(11) | 所有内部状态寄存器必须是可复位的，以便 RTL 级和门级描述能被复位成同一个已知状态做门级逻辑验证；**但这并不适用于流水线或同步寄存器** | `E3`（含"流水线/同步寄存器可例外"的例外条款） | `[通用]` |
| 可综合(12) | 对存在无效状态的 FSM 和其他时序电路（例：四位十进制计数器有六个无效状态），若想让无效状态下硬件行为也完全可控，**必须明确描述所有 2ⁿ 种状态的行为**，只有这样才能综合出安全可靠的状态机 | `F5`、`references/05` | `[通用]` |
| 可综合(13) | 一般情况下赋值语句中不能使用延迟，使用延迟的赋值语句是不可综合的；RTL 级中解决零延迟时钟倾斜问题是个例外 | `D5`、`I` | `[通用]` |
| 可综合(14) | **不要使用整型和 time 型寄存器**，否则将分别综合成 32 位和 64 位的总线 | `D6`、`I` | `[通用]` |
| 可综合(15) | 仔细检查代码中使用**动态指针**（用指针或地址变量检索的位选择或存储单元）、**循环声明**或**算术运算**的部分，因为这类代码综合后会生成大量的门，而且很难进行优化 | `G7`、`references/07`、`references/09` | `[通用]` |

**几条值得多说两句的**：

- **可综合(2) 是本规范 `E1` 的唯一教材依据**，也是最容易被忽视的一条。"经过门产生的时钟"在教材年代很常见（p.149 就有 `always @(posedge write)` 拿数据握手信号当时钟），今天则是同步设计的头号禁忌：门控时钟带毛刺、STA 无法建立时钟树模型、跨域路径无法约束。教材自己在 p.302 把"是否有个别模块没有按照同步设计的原则"列为后仿真出错的**最后也是最根本的病根**——后端约束修不好，只能回去改 RTL。
- **可综合(3)（DFT）本规范目前没有对应铁律**。原文要求"所有触发器都可复位 + 测试能通过外部引脚进行 + 没有冗余功能"，对应现代 scan 可测性设计。`[ASIC]` 应当硬要求；`[FPGA]` 通常不需要 scan，但"所有触发器可复位"这半条仍有价值（对应 `E3`）。这是本规范的一处已知空白。
- **可综合(4)「照抄标准模板」是全书方法论的浓缩**。p.192 小结说得更直白："可以借助于工具自动综合成电路结构的 Verilog 模块风格**非常有限**"。教材 p.382-383 给出的四个 always 模板是：`always @(Inputs)`（组合）/ `always @(Inputs) if(Enable)`（锁存）/ `always @(posedge Clock)`（同步）/ `always @(posedge Clock or negedge Reset)`（异步复位）。本规范 `assets/templates/` 就是这四个模板的现代化版本。**不要发挥想象力写"聪明"的 RTL**——综合器能识别的模式集合很小。
- **可综合(6)(7)(9) 是同一件事的三个面**：(6) 赋值要完备，(9) 敏感表要完备，(7) 不能自反馈。任缺其一，综合器都会插一个锁存器。教材 p.181 给的反例是全书最经典的一段：

```verilog
// 这是反例，不要抄 —— 教材 p.181 原文照录
// input a,b,c;  reg e,d;
always @(a or b or c)
    begin
        e = d & a & b;   // d 没在敏感表里 → 综合器为 d 隐含插入一个透明 latch
        d = e | c;       // 且 d 既被本块赋值又被本块读作输入 → 违反可综合(7) 组合反馈
    end
```

对应的现代正例（可直接综合，同时满足可综合(5)(6)(7)）：

```verilog
`default_nettype none
module opcode_dec (
    input  wire [2:0] opcode,
    input  wire [7:0] a,
    input  wire [7:0] b,
    output reg  [7:0] y,
    output reg        y_valid
);
    localparam [2:0] OP_ADD = 3'd0, OP_SUB = 3'd1,
                     OP_AND = 3'd2, OP_OR  = 3'd3;

    always @(*) begin
        y       = 8'd0;          // 块首默认值 → 满足 可综合(6)「不能有不完全赋值」
        y_valid = 1'b0;
        case (opcode)
            OP_ADD: begin y = a + b; y_valid = 1'b1; end
            OP_SUB: begin y = a - b; y_valid = 1'b1; end
            OP_AND: begin y = a & b; y_valid = 1'b1; end
            OP_OR : begin y = a | b; y_valid = 1'b1; end
            default: ;           // 用块首默认值兜底
        endcase
    end
endmodule
`default_nettype wire
```

- **可综合(12) 是本规范 `F5` 的依据，也是最常被违反的一条**。状态数不是 2 的幂时，多出来的编码就是"无效状态"；不描述它们，电路在受扰跳进去之后能不能回来就完全交给综合器的化简结果去决定了。教材举的例子（四位十进制计数器有六个无效状态）很朴素但很准。

## 3. p.381「设计流程」7 步（原文全录）

原书前言：「围绕着设计流程作多次反复是必要的……而且设计流程必须根据所设计的器件和特定的应用做必要的改动。」

| 步 | 原文 | 本规范对应 |
|---|---|---|
| (1) | 系统分析和指标的确定 | `SKILL.md` §0「先把设计契约写下来」5 问 |
| (2) | 系统划分：顶级模块；模块大小估计；预布局 | `references/08` |
| (3) | 模块级设计（对每一模块）：写 RTL 级 Verilog；**综合代码检查**；写 Verilog 测试文件；Verilog 仿真；写综合约束、边界条件和层次；预综合以分析门的数量和延时 | `SKILL.md` §2（`rtl_lint.py`）、`references/10`、`references/12` |
| (4) | 芯片综合：写 Verilog 测试文件；Verilog 仿真；综合；门级仿真 | `references/12` |
| (5) | 测试：修改门级网表以便进行测试；产生测试矢量；对可测试网表进行仿真 | 本规范未覆盖（DFT，见 §2 可综合(3)） |
| (6) | 布局布线以使设计的逻辑电路能放入芯片 | `references/12` |
| (7) | 布局布线后仿真、故障覆盖仿真和定时分析 | `references/12` |

**注意第 (3) 步里的「综合代码检查」**：教材在 2000 年代就把"写完 RTL 先做代码检查、再仿真"写进了流程。本规范 §2 的 `rtl_lint.py`（`verilator --lint-only -Wall` + `yosys proc+check`）正是这一步的现代实现——教材年代没有开源 lint，这一步只能靠人眼和综合器 warning。

## 4. p.180「13.3 综合的一般原则」4 条（原文全录）

| # | 原文摘要（p.180） | 本规范条款 | 范围 |
|---|---|---|---|
| 13.3(1) | 综合之前一定要进行仿真。**如果不做仿真，没有发现的逻辑错误会进入综合器，使综合的结果产生同样的逻辑错误** | `references/10`、`references/12` | `[通用]` |
| 13.3(2) | 每一次布局布线之后都要进行仿真，在器件编程或流片之前要做最后的仿真 | `references/12` | `[FPGA]` `[ASIC]` |
| 13.3(3) | 用 Verilog 描述的**异步状态机是不能综合的**，应避免用综合器来设计；一定要设计则可用电路图输入的方法 | `F6` | `[通用]` |
| 13.3(4) | 如果要为**电平敏感的锁存器**建模，使用**连续赋值语句**是最简单的方法 | 见 §8.5（本规范不采用此写法） | `[通用]` |

**13.3(3) 的机理（p.178 展开）**：异步状态机"不容易规范触发的瞬间，因此不容易判别触发脉冲是正常的触发还是冒险竞争产生的毛刺"；而且"目前大多数综合工具在对异步状态机进行逻辑优化时会胡乱地简化逻辑，使综合后的异步状态机不能正常工作"。这是本规范 `F6`「**绝不要**用综合器设计异步状态机」的完整理由，比"不推荐"强得多。

## 5. p.180-181「13.4 语言指导原则」（原文全录）

原书 13.4 在 p.180-185 范围内**只有两个小节**：「1. always 块」6 条、「2. 赋值」2 条（不存在独立编号的 if / case / 端口小节）。

### 5.1 「1. always 块」6 条

| # | 原文摘要 | 页 | 本规范条款 |
|---|---|---|---|
| 13.4-1(1) | 每个 always 块只能有一个事件控制 `@(event-expression)`，而且要紧跟在 always 关键字的后面 | p.180 | `I`（禁块内二次事件控制） |
| 13.4-1(2) | always 块可表示时序或组合逻辑；也可**既表示电平敏感的透明锁存器又同时表示组合逻辑，但不推荐**，因为容易产生错误和多余的透明锁存器 | p.180 | `C3`、`references/03` |
| 13.4-1(3) | 带 `posedge`/`negedge` 的事件表达式表示沿触发的时序逻辑；没有则表示组合逻辑或电平敏感锁存器。多个沿和多个电平之间必须用 `or` 连接 | p.180 | `C2`、`D1`、`references/03/04` |
| 13.4-1(4) | 每个表示时序的 always 块只能由**一个时钟跳变沿**触发，置位或复位最好也由该时钟跳变沿触发 | p.180 | `D4` |
| 13.4-1(5) | 每个在 always 块中赋值的信号都必须定义成 `reg` 型或整型 | p.180 | `references/02` |
| 13.4-1(6) | always 块中应避免**组合反馈回路**；生成组合逻辑的 always 块中赋值的所有信号必须有明确的值，否则综合器会警告"插入了锁存器"；若存在综合器认为不是电平敏感锁存器的组合回路，**综合器会发出错误信息** | p.180-181 | `C3`、`C5` |

13.4-1(6) 后面紧跟着一段专门的解释（p.181），是全书对"敏感表漏项 = 隐含 latch"讲得最透的一段：漏列的信号"变化不会立刻引起所赋值的变化，而必须等到敏感电平列表中某一个信号变化时，它的作用才显现出来，也就是相当于存在着一个透明锁存器"。反例即 §2 引用的 `e = d & a & b;`。

**注意 13.4-1(6) 里"警告"与"错误"的区别**：不完全赋值 → 综合器**警告**（插入 latch，代码照样综合过）；真正的组合环路 → 综合器**报错**。前者更危险，因为它不拦你。这正是本规范 §2 要求 `yosys proc+check` 必须跑的原因 `[工具]`——人眼漏读一条 warning 太容易了。

## 6. p.197「14.2 Verilog 模块编程要点」8 条（原文全录）

原书 p.196 导语：「掌握可综合风格的 Verilog 模块编程的以下 8 个原则对读者会有很大的帮助。**在编写 Verilog 代码时必须牢记这 8 个要点，才能在综合布局布线后的仿真中避免出现冒险竞争现象。**」
第 14 章末（p.212）小结再次给出这 8 条，措辞略有出入，并加了一句结论：「遵循以上原则，**有助于正确的编写可综合硬件，并且可以消除 90%～100% 在仿真时可能产生的竞争冒险现象**。」

| # | p.197 原文 | p.212 小结措辞 | 本规范条款 |
|---|---|---|---|
| 要点(1) | 时序电路建模时，用非阻塞赋值 | 原则 1（同） | `D1` |
| 要点(2) | 锁存器电路建模时，用非阻塞赋值 | 原则 2（同） | `references/03`（本规范原则上不推断 latch） |
| 要点(3) | 用 always 块建立组合逻辑模型时，用阻塞赋值 | 原则 3：用 always 块写组合逻辑时，采用阻塞赋值 | `C1` |
| 要点(4) | **在同一个 always 块中建立时序和组合逻辑电路时，用非阻塞赋值** | 原则 4（同） | 见 §8.3（本规范倾向拆块） |
| 要点(5) | 在同一个 always 块中不要既用非阻塞赋值又用阻塞赋值 | 原则 5（同） | `D2` |
| 要点(6) | 不要在一个以上的 always 块中为同一个变量赋值 | 原则 6：不要在多个 always 块中为同一个变量赋值 | `D3` |
| 要点(7) | 用 `$strobe` 系统任务来显示用非阻塞赋值的变量值 | 原则 7（同） | `references/10` |
| 要点(8) | 在赋值时不要使用 `#0` 延迟 | 原则 8（同） | `D5`、`I` |

**这 8 条的共同机理在 p.197「14.3 层次化事件队列」**：IEEE 1364-1995 §5.3 把当前仿真时刻分成 4 个队列——①动态事件队列（阻塞赋值、**计算**非阻塞赋值的 RHS、连续赋值、`$display`、原语输入输出变化）②停止运行事件队列（`#0` 延时阻塞赋值）③非阻塞事件队列（**更新**非阻塞赋值的 LHS）④监控事件队列（`$monitor`、`$strobe`）。关键结论是原书黑体：「**而非阻塞赋值语句 LHS 的更新却不由动态事件队列调度。**」

这一句同时解释了三件事：①为什么时序逻辑要用 `<=`——RHS 求值与 LHS 更新分属两个队列，同一时钟沿上所有寄存器读到的都是**旧值**，结果与 always 块的书写/调度顺序无关（要点(1)(6)）；②为什么 `$display` 看不到非阻塞赋值的新值——它在动态队列，LHS 更新在非阻塞队列（要点(7)）；③为什么 `#0` 救不了竞争——它只是把事件挪到停止运行队列，仍排在非阻塞队列之前（要点(8)）。教材 p.198 直接点名 `#0` 是"对 Verilog 理解不够深入的设计人员"的做法。

**教材用一组实验把这件事量化了（p.199-202，移位寄存器 4 种写法 × 2 种赋值）**，结论逐字照录（p.202）：
> （1）4 种阻塞赋值设计方式中有 1 种可以保证仿真正确；（2）4 种阻塞赋值设计方式中有 3 种可以保证综合正确；（3）4 种非阻塞赋值设计方式全部可以保证仿真正确；（4）4 种非阻塞赋值设计方式全部可以保证综合正确。

「4 种阻塞里 3 种综合正确、只有 1 种仿真正确」正是**综合前后仿真不一致**的定量刻画——这是本规范 `D1`~`D3` 存在的全部理由。教材因此在 p.202-203 下了"必须"级别的结论：「建议大家在编写 Verilog 时序逻辑时**必须要用非阻塞赋值**的方式」「在描述时序逻辑时，**必须养成使用非阻塞赋值的习惯**（无论用多个 always 块或单个 always 块描述时）」。

## 8. 教材中已过时或与现代实践冲突之处

这一节**不是挑教材的错**。教材写作于 Verilog-1995/2001 交替、CPLD 与早期 FPGA 为主的年代，其**道理**至今全部成立，过时的只是**写法**与**器件假设**。本规范凡与教材写法不同之处，均在此列出并说明改动理由。

### 8.1 敏感表：手工列全 vs `always @*` `[V2001]`

- **教材立场**：可综合(5)（p.380）与 13.4-1(3)（p.180）都要求把所有输入信号手工列进敏感表，正文示例一律写 `always @(a or b or c)` / `always @(addr or in1 or ... or nCS)`（p.146-147）。
- **教材自己也说了另一半**：**p.81** 明确介绍了 `@*` 与 `@(*)`，原话是「如果组合逻辑块语句的输入变量很多，那么编写敏感列表会很烦琐并且容易出错」，并给出对照例 6.8；**p.80-81** 还收录了 Verilog-2001 用逗号代替 `or` 的写法（含 `always @(posedge clk, negedge reset)`）。
- **现代做法**：`[V2001]` 一律 `always @(*)`；`[SV]` 用 `always_comb`（还能在漏赋值时报错）。它把"漏列"这一整类 bug 从根上消掉了。
- **本规范取舍**：`C2` 采用 `always @(*)` / `always_comb`。这**不是推翻**可综合(5)，而是用工具自动完成它要求的事——教材要"列全"，`@(*)` 保证一定列全。

### 8.2 `casex` `[通用]`

- **教材立场**：p.177「建议采用 case，**casex** 或 casez 语句来建立状态机的模型」；p.55-56 把 casez/casex 作为处理 don't-care 的推荐手段并给出 `casex(r^mask)` 掩码比较示例。p.331 的实验代码里也用了 `casex`。
- **冲突点**：`casex` 把**控制表达式**中出现的 x 也当作 don't care。RTL 仿真中输入是 x 时，`casex` 会随便匹配上某个分支，把 x 传播掩盖掉；到门级仿真或硅片上行为可能完全不同。这是"仿真通过、实物不对"的典型来源。
- **本规范取舍**：`G5` 禁止 `casex`；`casez` 仅在明确知道自己在做什么（如指令译码，且控制表达式保证无 x）时使用。教材的 `casez` 指令译码示例（p.55-56）本身是合理用法。

### 8.3 「同一个 always 块里混写时序与组合、统一用 `<=`」`[通用]`

- **教材立场**：p.197 要点(4) / p.208 原则 4：「在同一个 always 块中建立时序和组合逻辑电路时，用非阻塞赋值」，例 14.22 `nbex2` 即 `q <= a ^ b;`。
- **教材也给了拆块写法**：p.208 例 14.23 `nbex1`——组合块用 `=`、时序块用 `<=`，原话是"用两个 always 块实现以上逻辑**也是可以的**"。
- **本规范取舍**：默认**拆块**（`C1` + `D1`），理由是可读性与可综合性边界清晰、便于 lint 判定、也便于把组合部分复用。教材要点(4) 在"组合部分极其简单（一两个门）"时仍然成立，本规范不禁止，但需要在模块头注释里说明。**这是取舍差异，不是对错。**

### 8.4 `case` 的 `default` 赋 `'bx` vs 回安全态 `[通用]`

教材**自身两种主张并存**，如实呈现：

| 主张 | 出处 | 理由 |
|---|---|---|
| `default: state <= 5'bxxxxx;` | p.177、p.180、13.4-2(2)（p.181）；例 13.2 `default: out=8'hx;`（p.182）；例 12.1/12.4 `2'bxx`（p.170、p.173） | `'bx` 被综合器解释为无关状态 → 删除多余译码 → 电路最简洁；且**与真实硬件上电状态不确定相一致**，避免综合前后仿真不一致 |
| `default: state <= Idle;` | **p.171**（"以确保回到 Idle 状态"）、p.177 的例外条款（"否则会引起死锁"）；例 12.2（p.171）、p.343 实验代码 | 有多余状态时，若不显式回有效状态，状态机偶然进入多余状态后可能**死锁** |

- **现代实践**：安全关键 / 高可靠设计一律要求显式回安全态（安全状态机）；`'bx` 方案依赖综合器把 x 当 don't care 化简，在不同工具上结果不一，且门级仿真时 x 会传播开。
- **本规范取舍**：`F4` + `SKILL.md` §1.F 结论——**默认显式回安全态**，详细论证见 `references/14-disputes.md`。教材 p.177 关于"仿真启动即进 default 会掩盖上电不定态"的顾虑，本规范用 testbench 里显式的复位序列来解决，而不是靠 `'bx`。

### 8.5 锁存器建模用连续赋值 `[通用]`

- **教材立场**：13.3(4)（p.180）「为电平敏感的锁存器建模，使用连续赋值语句是最简单的方法」；例 13.12 `assign q = clk ? data : q;`、例 13.13 `assign q = reset ? 0 : (set ? 1 : (clk ? data : q));`（p.187）。
- **问题**：`q` 出现在自己右侧，构成**组合环路**。多数现代 lint / 综合工具会报组合环并拒绝综合，可移植性差。教材自己在 13.4-1(2)（p.180）又不推荐用 always 混合描述锁存器，两处需合起来读。
- **本规范取舍**：可综合 RTL 中**原则上不推断 latch**；确实需要时显式实例化库单元或用 `always @(*)`（`[SV]` `always_latch`）并在注释中写明"这是有意的 latch"。

### 8.6 片内三态与 `inout` `[FPGA]` `[ASIC]`

- **教材立场**：第 10、11 章大量使用片内三态总线（`SampleOfBus` p.148-149、三态数据通路 p.157-158、`trist1`/`bidir` p.186-187），把它当作模块间共享数据通道的标准手段。
- **现实**：现代 FPGA 内部**没有三态资源**，综合器会把片内三态改写成 MUX（教材自己在 p.147 给的 `Mux_8` 就是这个替代品）；`[ASIC]` 标准单元流程中片内三态总线也早已被禁止（无法做 DFT、有直通电流风险、需要 keeper）。
- **本规范取舍**：`H4`——顶层之外不出现 `inout` / 三态；片内一律 MUX。教材关于"任何时间片段只能有一个部件发送"（p.148）的**结论完全正确**，只是实现手段换成了 MUX + 使能仲裁。
