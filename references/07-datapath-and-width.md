# 07 · 数据通路：位宽、符号与运算

位宽 bug 是 RTL 里**最安静**的一类错误：不报错、不告警（除非开了 lint）、
仿真波形看上去也很正常，直到某个边界值把高位截掉。
Verilog 的位宽与符号规则相当反直觉，这一篇就是把这些规则摊开讲。

---

## 本篇速览

1. **表达式的位宽由上下文决定**，包括左值——`assign y8 = a4 + b4;` 里加法是按 8 bit 算的。
2. **只要有一个操作数是无符号的，整个表达式就变成无符号**。一个 `-1` 能毁掉整条有符号运算链。
3. 无位宽的字面量（`1`、`'d5`）是 **32 位**的，混进窄表达式里会悄悄把运算宽度撑到 32。
4. **拼接 `{}` 和移位的右操作数是自定宽度的**，不受上下文影响——这是最常被忽略的例外。
5. 赋值两侧位宽必须显式相等；要截断/扩展就**明写出来**，让读者看见你是故意的。

---

## 一、位宽推导

### R-07-01 表达式位宽由"上下文"决定，左值也参与 `[通用]`

Verilog 先把表达式里所有**上下文决定（context-determined）**的操作数、连同赋值左值一起，
取最大位宽，然后**按这个位宽做整个运算**。

```verilog
wire [3:0] a, b;
wire [4:0] sum5;
wire [3:0] sum4;

assign sum5 = a + b;   // 按 5 bit 运算 -> 进位保留，sum5[4] 是进位
assign sum4 = a + b;   // 按 4 bit 运算 -> 进位丢失（这常常正是 bug）
```

> 注意左值的类型：`assign` 是**连续赋值，只能驱动 net（`wire`）**。
> 对 `reg` 用 `assign` 在纯 Verilog 下是编译错误
> （`verilator --language 1364-2001` 会报 `CONTASSREG`，并直接点名 IEEE 1364-2005 §6.1）。
> `reg` 只能在 `always` / `initial` 这类过程块里被赋值。

**这意味着**：想拿到进位，就把左值开宽一位；`{carry, sum} = a + b;` 也可以，
因为拼接的左值总宽度是 5。

### R-07-02 自定宽度（self-determined）的三个例外 `[通用]`

以下位置**不受上下文影响**，按自身宽度计算，是最容易踩的坑：

| 位置 | 说明 |
|---|---|
| 拼接 `{}` 的每个操作数 | `{a, b}` 中 a、b 各按自身宽度 |
| 重复拼接的重复次数 | `{N{x}}` 的 N 必须是常量 |
| 移位运算的**右**操作数 | `a << b` 中 b 自定宽度（左操作数 a 仍是上下文决定） |

```verilog
wire [3:0] a, b;
wire [7:0] y_bad, y_ok;

assign y_bad = {a + b};   // 拼接内部按 4 bit 算，进位丢了，再零扩展到 8
assign y_ok  = a + b;     // 这才是按 8 bit 算
```

**结论**：不要用 `{}` 去"扩展位宽"，它不会把运算宽度带进去。要扩展就显式写。

### R-07-03 无位宽字面量是 32 位 `[通用]`

`1`、`0`、`'d5`、`'h1F` 都是 32 位（`integer` 宽度）。混进表达式会把运算宽度撑到 32 位。

```verilog
reg [7:0] cnt;
// 右边按 32 bit 算，再截断回 8 bit 存进 cnt。多数时候结果碰巧对，
// 但它掩盖了你的真实意图，而且 lint 会报 WIDTHTRUNC。
always @(posedge clk) cnt <= cnt + 1;

// 推荐：位宽写全，意图明确，lint 干净
always @(posedge clk) cnt <= cnt + 8'd1;
```

`[SV]` 可以写 `cnt + 1'b1`，或用 `'0` / `'1` 这类上下文自适应字面量。

### R-07-04 所有字面量写全位宽与进制 `[通用]`

`8'd0` / `4'b1010` / `16'hDEAD`。不要裸写 `0`、`1`。
参数化模块里用 `{WIDTH{1'b0}}` 或 `{{(WIDTH-1){1'b0}}, 1'b1}` 构造合适宽度的常量。

## 二、符号

### R-07-05 一个无符号操作数就让整个表达式变无符号 `[通用]` ★高频 bug★

```verilog
reg signed [7:0] s;
reg        [7:0] u;

// s 是有符号的，但 u 是无符号的 -> 整个比较按无符号做
// s = -1 时会被当成 8'hFF = 255，于是这个条件恒为真
if (s < u) ...

// 正确：显式统一符号
if (s < $signed({1'b0, u})) ...
```

### R-07-06 `reg [N:0]` 默认是无符号的 `[通用]`

要有符号必须写 `reg signed [N:0]`（`[SV]` 用 `logic signed`）。
端口同理：`input signed [7:0] a`。

一个经典陷阱：

```verilog
reg [7:0] a;
if (a - 1 >= 0) ...      // 恒为真：无符号数永远 >= 0
```

`a = 0` 时 `a - 1` 到底等于多少？按 R-07-03，字面量 `1` 是 **32 位**的，
所以整个表达式按 32 位无符号计算，结果是 **4294967295**，不是 255。
想要 8 位回绕（得到 255），必须把字面量的位宽也写成 8 位：

```verilog
wire [7:0] am1_32 = a - 1;      // 32 位算完再截断，中间值是 4294967295
wire [7:0] am1_8  = a - 8'd1;   // 全程 8 位，a=0 时得到 8'd255
```

两种写法**最终存进 8 位变量的结果相同**，但中间表达式的宽度不同——
一旦这个中间值参与比较（就像上面的 `>= 0`）或再拼接，差别就会暴露出来。

### R-07-07 有符号数的位宽扩展要用 `$signed` 或显式符号位复制 `[通用]`

```verilog
wire signed [7:0]  a;
wire signed [15:0] b1, b2, b3;

assign b1 = a;                        // 上下文决定 + a 有符号 -> 自动符号扩展，OK
assign b2 = $signed({{8{a[7]}}, a});  // 显式写法，最不容易看错
assign b3 = {{8{a[7]}}, a};           // 位模式对，但拼接结果是无符号的！
```

最后一行是个陷阱：拼接的结果**永远是无符号的**，即使操作数有符号。
如果 b 之后还要参与有符号运算，必须再套 `$signed()`。

## 三、运算与可综合性

### R-07-08 乘法可综合，除法和取模基本不可用 `[通用]`

- `*` → 综合成乘法器（`[FPGA]` 映射到 DSP，`[ASIC]` 映射到乘法器宏）。
- `/`、`%` 除数是 **2 的幂的常量**时会被优化成移位/取低位，其余情形会综合出巨大的组合除法器，
  时序几乎必然崩。需要真除法请用多周期的迭代除法器 IP。

```verilog
assign q = a >> 3;        // 等价 a / 8，推荐
assign r = a & 8'h07;     // 等价 a % 8，推荐
```

教材 p.326 的说法是一致的：把复杂运算拆成几步，用寄存器存中间结果，在多个周期内完成。

### R-07-09 变长移位比想象中贵 `[通用]`

`a << b`（b 是变量）会综合成桶形移位器（barrel shifter），面积随位宽平方增长。
若 b 的取值有限，用 `case` 显式列出往往更省。

### R-07-10 变量索引的位选用 indexed part-select `[V2001]`

```verilog
// 反例，不要抄：位选的上下界都必须是常量，这样写编译不过
assign y = data[i*8+7 : i*8];

// 正例：indexed part-select，起点可变、宽度是常量
assign y = data[i*8 +: 8];   // 从 i*8 向上取 8 位
assign y = data[i*8 -: 8];   // 从 i*8 向下取 8 位
```

宽度必须是常量；起点可以是变量。教材 p.381 可综合(15) 也提醒过：
大量使用动态指针索引会综合出很多门且难以优化。

### R-07-11 位宽相关的 lint 告警不许豁免 `[工具]`

Verilator 的 `WIDTHTRUNC` / `WIDTHEXPAND` 是最有价值的两条规则。
它们几乎总是指向真问题，或至少指向"意图不明确"。
如果确实要截断，请显式写出来，让告警自然消失：

```verilog
assign y8 = a16[7:0];              // 明写截断，不是让工具替你截
assign y16 = {8'd0, a8};           // 明写零扩展
assign y16 = $signed(a8);          // 明写符号扩展（a8 须为 signed）
```

## 四、流水线与面积/速度取舍

### R-07-12 拆流水线是打断长组合链的首选手段 `[通用]` `[教材]` p.149-154

教材第 10.6 节把流水线称为"面积换速度"的具体体现。规则：

- 每一级之间插寄存器，把长组合路径切成若干短段，主频随之提高。
- 代价是**延迟增加**（吞吐不变）和**寄存器面积增加**。
- 控制信号（valid）必须与数据**同步打拍**，否则数据和它的有效标志会错位。

```verilog
// 数据与 valid 必须走同样的级数
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        s1_valid <= 1'b0;
        s2_valid <= 1'b0;
    end else begin
        s1_valid <= in_valid;
        s2_valid <= s1_valid;
    end
end
always @(posedge clk) begin
    s1_data <= f(in_data);
    s2_data <= g(s1_data);
end
```

注意上面第二个块**没有复位**——这是 R-06-07 允许的数据通路豁免，
前提是 valid 链有复位（第一个块），数据在 valid 为 0 时不会被下游使用。

### R-07-13 资源共享不要凭猜测 `[通用]` ⚠️

流传很广的说法是"把互斥的算子写进同一个条件表达式，综合器就会共享它们"，
例如 `y = sel ? (a*b) : (c*b);` 会共享一个乘法器。

**但这条在调研中找不到可移植的一手依据**——不同综合器、不同选项下行为不同。
本规范的态度：**不要在 RTL 里靠写法去"暗示"资源共享**。
需要控制资源时，用综合报告实测（`report_utilization` / `report_resources`），
或直接把共享的算子显式提取成一个实例：

```verilog
// 显式共享：只有一个乘法器，谁用它由 MUX 决定
wire [15:0] mul_a = sel ? a : c;
wire [31:0] product = mul_a * b;
```

这样意图写在代码里，不依赖工具的推断。
