# 05 · 状态机（FSM）设计规范

> 本篇展开 `SKILL.md` §1.F 的 6 条铁律，并把业界与教材在 FSM 上的分歧摊开讲清。
> 与 `SKILL.md` 冲突时以 `SKILL.md` 为准；若发现铁律本身有问题，见文末「⚠️ 与主规范的冲突 / 待裁决」。
> 每条规则标注来源 `[教材]`(书页号) / `[业界]`(文档名) / `[工具]`(Verilator 5.024 + Yosys 0.33 实测) 与适用范围
> `[通用]` `[FPGA]` `[ASIC]` `[V2001]` `[SV]`。

---

## 本篇速览

1. **默认三段式**（状态寄存 / 次态组合 / 输出寄存）；一段式、两段式不是错，各有适用场景，见 §1 选型表。`[通用]`
2. **次态组合块第一行永远是 `next_state = state;`**，然后 `case` 只写"偏离默认"的分支——这是唯一可靠的消 latch 手段。`[通用]`
3. **编码不写死**：符号名用 `localparam`(V2001) / `enum`(SV)，具体编码交给综合脚本。`[FPGA]` 默认 one-hot，`[ASIC]` 默认二进制——**两边结论相反，因为 FPGA 触发器富余而 LUT 是瓶颈，ASIC 反之**（§4）。
4. **`default` 赋确定的安全态，不赋 `x`**。教材 p.177 主张赋 `'bx`，本规范不采纳，理由与实测数据见 §5。
5. **`default` 只是必要条件，不是充分条件**：综合器会把"证明不可达"的恢复逻辑优化掉。真要防非法态，得靠 sparse encoding + 显式检测 + 工具选项（§6）。
6. **输出必须寄存化**（三段式的第三段）；`[ASIC]` 高速场合可用"输出编码的状态指定"让输出直接从 FF 引出（§3）。
7. **绝不用综合器设计异步状态机**（§7）。

## 0. 先把结构说清楚

同步状态机只有三个部件 `[教材]` p.166 图 12.1：

```
     ┌───────────────┐        ┌──────────────┐
输入 ─┤ F：次态组合逻辑 ├─ next ─┤ 状态寄存器组  ├─┬─ state
     └───────────────┘        └──────┬───────┘ │
              ▲                     clk        │
              └────────────── state ───────────┘
                     ┌──────────────┐
   state (+输入) ────┤ G：输出组合逻辑 ├──── 输出
                     └──────────────┘
```

- 次态 = F(当前状态, 输入)；输出 = G(当前状态, 输入)。**F 和 G 必须是纯组合逻辑** `[教材]` p.166。
  F/G 里一旦混进锁存器，状态机就多出一批你没画在状态图上的状态，仿真和综合会开始分家。
- 所有状态触发器挂**同一个时钟**，状态只在时钟沿改变 `[教材]` p.166。
- 现代实现一律用**正沿 D 触发器**；JK/锁存器已基本不用 `[教材]` p.166。

写 RTL 之前先画状态转移图，并回答：状态数？复位态？每个状态的输出？哪些跳转依赖输入？
`[教材]` p.175 给的 5 步法（逻辑抽象 → 状态化简 → 状态分配 → 求方程 → 出电路）中，
第 2、4、5 步今天由综合器完成，**人只需要做好第 1 步（状态图）和第 3 步（编码策略）**。

> 状态化简的判据是**等价状态**：相同输入下转到同一状态且输出相同的两个状态可以合并 `[教材]` p.175。
> 合并等价状态是唯一"免费"的面积优化，写完状态图先扫一遍。

## 1. 一段式 / 两段式 / 三段式

三种写法**功能等价、都可综合**，差别在可维护性、输出时序、以及关键路径落在哪里。
`[教材]` p.174 对同一个状态机给了 4 种模型，并明确说"它们都是可综合的，在设计复杂程度不同的
状态机时有它们各自的优势……用不同的综合器综合出的逻辑电路可能会有些不同，但逻辑功能是相同的"。
**所以这不是对错之争，是取舍。**

### 1.1 一段式：一个时序块搞定状态 + 输出

```verilog
// 正例（经 verilator -Wall + yosys 验证）：一段式，适合状态少、输出少的小控制器
`default_nettype none
module fsm1_oneseg (
    input  wire clk, input wire rst_n,
    input  wire start, input wire done,
    output reg  busy, output reg ack
);
    localparam [1:0] S_IDLE = 2'd0, S_RUN = 2'd1, S_WAIT = 2'd2, S_ACK = 2'd3;
    reg [1:0] state;

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            state <= S_IDLE; busy <= 1'b0; ack <= 1'b0;
        end else begin
            // 先赋默认值再在分支里覆盖：非阻塞赋值同一时刻多次写同一变量以最后一次为准，
            // 所以这个手法在时序块里同样成立，且能防止"忘了清输出"这类 bug。
            busy <= 1'b0;
            ack  <= 1'b0;
            case (state)
                S_IDLE: if (start) begin state <= S_RUN;  busy <= 1'b1; end
                S_RUN:  begin              state <= S_WAIT; busy <= 1'b1; end
                S_WAIT: begin busy <= 1'b1; if (done) state <= S_ACK; end
                S_ACK:  begin ack  <= 1'b1; state <= S_IDLE; end
                default: state <= S_IDLE;
            endcase
        end
    end
endmodule
`default_nettype wire
```

- **优点**：输出天然寄存化、无毛刺；没有组合次态块就没有 latch 风险；代码最短。
- **缺点**：状态转移和输出赋值缠在一起，状态一多就没法读、没法改；
  想知道"busy 在哪些状态为 1"必须把整个 case 读一遍。教材 [例 12.1] 就是这种写法，
  而它的 `Idle` 分支在两个版本里对 `K1` 的赋值就出现了不一致（`[教材]` p.169 vs p.170，
  调研文件 B06 已把它标为疑似印刷错误）——**这正是一段式最典型的失误模式**。
- **适用**：≤4~5 个状态、输出 ≤2 个、逻辑不会再长的小控制器。`[通用]`

### 1.2 两段式：时序状态寄存 + 组合次态与输出

```verilog
// 正例（已验证）：两段式，输出是组合的
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) state <= S_IDLE;
        else        state <= next_state;
    end

    always @(*) begin
        next_state = state;      // 默认保持当前态 —— 这一行是消 latch 的关键
        busy       = 1'b0;       // 所有输出先给默认值
        ack        = 1'b0;
        case (state)
            S_IDLE: begin if (start) next_state = S_RUN; end
            S_RUN:  begin busy = 1'b1; next_state = S_WAIT; end
            S_WAIT: begin
                        busy = 1'b1;
                        if (done) begin
                            ack        = 1'b1;   // Mealy：本拍就响应，比 Moore 早一拍
                            next_state = S_ACK;
                        end
                    end
            S_ACK:  begin next_state = S_IDLE; end
            default: next_state = S_IDLE;
        endcase
    end
```

- **优点**：状态转移图和代码一一对应，最好读；输出可以做成 Mealy（比 Moore 早一拍响应）；
  这是 lowRISC / OpenTitan 的官方写法——*"State machines use an enum to define states, and must be
  implemented with two process blocks: a combinational block and a clocked block."* `[业界]` lowRISC Verilog Coding Style Guide。
- **缺点**：输出是组合的 ⇒ **带毛刺**，且把本模块的组合延时直接接到下游关键路径上。
  组合输出绝不能去当别的模块的时钟、复位或写使能。
- **适用**：模块内部使用的控制信号、需要 Mealy 早一拍语义的握手；对外接口建议再打一拍。`[通用]`

### 1.3 三段式：再加一段输出寄存

```verilog
// 正例（已验证）：三段式 —— 本规范默认写法
    // 段 1：状态寄存
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) state <= S_IDLE;
        else        state <= next_state;
    end

    // 段 2：次态译码（纯组合）
    always @(*) begin
        next_state = state;
        case (state)
            S_IDLE: if (start) next_state = S_RUN;
            S_RUN:             next_state = S_WAIT;
            S_WAIT: if (done)  next_state = S_ACK;
            S_ACK:             next_state = S_IDLE;
            default:           next_state = S_IDLE;
        endcase
    end

    // 段 3：输出寄存化
    // 用 next_state 译码 => 输出与它代表的状态同拍出现；
    // 用 state 译码     => 输出比状态晚一拍。两者都对，选一个并写进注释。
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            busy <= 1'b0;
            ack  <= 1'b0;
        end else begin
            busy <= (next_state == S_RUN) || (next_state == S_WAIT);
            ack  <= (next_state == S_ACK);
        end
    end
```

- **优点**：输出无毛刺、时序确定（clk→q + 一级布线），跨模块安全；
  三块各司其职，改哪块看哪块。教材 [例 12.4] 的多 always 块风格同源，
  原书结论：*"这种风格的描述比较适合大型的状态机，查错和修改比较容易。
  Synopsys 公司的综合器建议使用这种风格来描述状态机。"* `[教材]` p.174。
- **缺点**：输出比两段式晚一拍（用 `next_state` 译码可补回来，但那一段又变成"组合译码 + 打拍"，
  次态逻辑的关键路径会变长）；代码更长。
- **适用**：**默认选它**，尤其是输出要跨模块、要接总线、状态数 >5 的场合。`[通用]`

### 1.4 选型表

| 维度 | 一段式 | 两段式 | 三段式 |
|---|---|---|---|
| 输出是否寄存 | 是 | 否（组合，有毛刺） | 是 |
| 输出延迟 | 与状态同拍 | 比状态早（Mealy）或同拍 | 晚一拍（或用 `next_state` 补回） |
| latch 风险 | 无（时序块） | 有（必须块首赋默认值） | 有（同左） |
| 可读性 / 可改性 | 差（状态一多就烂） | 好 | 好 |
| 关键路径 | 输入→次态→FF | 输入→次态/输出→下游 | 输入→次态→FF，输出独立 |
| 适用状态数 | ≤5 | 任意 | 任意 |
| 本规范 | 允许（小 FSM，注释说明理由） | 允许（内部信号） | **默认** |

> `SKILL.md` F1 定的是"默认三段式"，不是"只准三段式"。选了别的，在模块头注释里写一句为什么。

### 1.5 教材的第四种风格：一个输出一个 always 块

`[教材]` p.173 12.3.4 建议：*"为了调试方便，还常常把每一个输出开关写成一个个独立的 always 组合块。
在调试多输出状态机时，这样做比较容易发现问题和改正模块编写中出现的问题。"*

这个建议今天仍然成立，但要打两个补丁：
1. 教材写的是 `always @(state or Reset or A)` 这种手写敏感表（Verilog-1995 风格），
   本规范一律用 `always @(*)` / `[SV]` `always_comb`（`SKILL.md` C2），敏感表漏项这个坑从根上消掉。
2. 教材那几个输出块是**组合**输出。本规范要求输出寄存化，所以落地形式是
   "一个输出一个时序 always 块"，或者干脆合并成三段式的第三段。输出多到需要拆块时，拆。

## 2. Mealy 与 Moore

- **判据只有一条**：输出是否依赖输入。输出 = G(状态) 是 Moore；输出 = G(状态, 输入) 是 Mealy `[教材]` p.167。
  两者的电路差别**只在输出逻辑 G**，状态部分完全相同。
- **不要为分类焦虑**。`[教材]` p.167-168 原文：*"在实际设计工作中，其实大部分状态机都属于 Mealy 状态机……
  把状态机精确地分为这类或那类，其实并不重要，重要的是设计者如何把握输出的结构能满足设计的整体目标，
  包括定时的准确性和灵活性。"* 一个真实模块里通常几个输出是 Moore、几个是 Mealy。
- **工程上真正要管的是三件事**：

| 关心点 | Moore | Mealy |
|---|---|---|
| 响应延迟 | 慢一拍（输入变化要先改状态） | 快一拍（输入直接穿到输出） |
| 毛刺 | 组合 Moore 输出仍可能有毛刺（状态位不同时翻转）；寄存后无 | 输入的毛刺会直接传到输出 |
| 状态数 | 通常更多（要为不同输出组合分状态） | 通常更少 |
| 时序 | 输入→FF 是一条路径，输出→下游是另一条 | 输入→输出→下游是一条**穿透**的组合长路径 |

- **本规范取舍** `[通用]`：
  - 需要早一拍响应（典型是 valid/ready 握手里的 `ready`）→ 用 Mealy，但**必须**在注释里写明它是组合穿透的，
    并保证上游驱动它的信号已经是寄存器输出（`SKILL.md` H3）。
  - 其余一律 Moore + 寄存化。**跨模块的输出永远寄存化**，不管 Mealy 还是 Moore。
  - 绝不允许出现"Mealy 输出 → 组合逻辑 → 另一个模块的 Mealy 输入"这种链，那是关键路径灾难现场。

## 3. 输出寄存化，以及"输出编码的状态指定"

### 3.1 为什么必须寄存化 `[通用]`

组合译码出来的输出，其毛刺来自**状态寄存器各位翻转时刻不一致**：`2'b01 → 2'b10` 的中间可能短暂出现
`2'b00` 或 `2'b11`，译码器就会吐出一个窄脉冲。这个脉冲在同步逻辑里被下一个时钟沿采样时通常无害，
但只要它被当作时钟、复位、写使能、或送去异步域，就是硬故障。

三种消除办法，按代价从低到高：

1. **输出打一拍**（三段式第三段）——默认做法。代价：一个时钟周期延迟 + 每个输出一个 FF。
2. **流水线化输出**（pipelined outputs）——在 G 之后加一整组同步寄存器 `[教材]` p.167 图 12.3。
   本质与 1 相同，只是把"打一拍"提升为架构约定。
3. **输出编码的状态指定**（output-coded state assignment）——见下。

### 3.2 输出编码的状态指定 `[ASIC]` `[通用高速]`

把输出直接指定为状态码的某几位，输出组合逻辑 G 退化成**只有连线** `[教材]` p.167、p.171-172 [例 12.3]。

```verilog
// 正例（已验证，教材 [例 12.3] 的可编译修正版）
// 位分配：bit4 = k2, bit3..bit1 = 区分位, bit0 = k1
localparam [4:0] IDLE          = 5'b0_000_0,
                 START         = 5'b0_001_0,
                 STOP          = 5'b0_010_0,
                 STOP_TO_CLEAR = 5'b1_100_0,
                 CLEAR         = 5'b0_100_0,
                 CLEAR_TO_IDLE = 5'b0_011_1;

assign k2 = state[4];   // 输出即状态位，无组合逻辑、无毛刺、无额外延时
assign k1 = state[0];
```

- **收益**：输出直接从 FF 的 Q 端引出，clk→q 之后立刻有效，是所有写法里输出时序最好的一种。
- **代价（教材原文明示，最容易被忽略）** `[教材]` p.171：
  *"开关的维持时间必须与状态维持的时间一致，如果要完全实现上面两例子的开关输出波形，需要增加状态才能实现。"*
  上面这个例子为了复现原波形，多出了 `STOP_TO_CLEAR`、`CLEAR_TO_IDLE` 两个过渡状态（4 状态 → 6 状态）。
- **强制要求**：用这种编码必须在 `localparam` 上方写出位段注释（教材 p.172 的 `K2_i_j_K1` 注释头就是范本），
  并用下划线把位段分开（`5'b0_000_0`）。不写注释的输出编码 = 不可维护。
- **与工具的冲突** `[FPGA]`：这种编码是"人为写死的"，必须同时关掉综合器的 FSM 自动重编码
  （AMD `FSM_ENCODING = user_encoding` 或 `none`），否则工具会重新编码，输出与状态位的对应关系当场作废。
  `[业界]` AMD UG901 v2025.1 Ch.3。

## 4. 状态编码

### 4.1 三种编码及其取舍 `[通用]`

| 编码 | 状态位数 | 次态组合逻辑 | 适合 |
|---|---|---|---|
| **二进制** | `ceil(log2(N))` | 较复杂（要译码） | `[ASIC]` 状态多、面积敏感 |
| **格雷码** | `ceil(log2(N))` | 与二进制相当 | 状态按固定顺序推进、要降低翻转功耗 |
| **独热码** | `N` | 最简单（比较 1 位即可） | `[FPGA]` 状态数中等、追求频率 |

教材 p.170 的立场是：**FPGA 实现的状态机建议采用独热码**——多用触发器但省组合电路，
速度和可靠性显著提高，而 FPGA 里触发器本来就"用不完"，总单元数无显著增加。

`[ASIC]` 情况相反：触发器面积昂贵，状态一多独热码的面积代价就显出来了，一般用二进制。

### 4.2 不要在 RTL 里写死编码方式 `[通用]` ★本规范的默认★

除了 §3.2 那种刻意的"输出编码"，**编码方式应该交给综合器决定**：

```verilog
// 推荐：只给符号名，具体编码由综合脚本的 FSM_ENCODING 属性控制
localparam [1:0] S_IDLE = 2'd0, S_RUN = 2'd1, S_WAIT = 2'd2, S_DONE = 2'd3;
```

**为什么**：同一份 RTL 要同时面向 FPGA 和 ASIC 时，最优编码是相反的（见上表）。
把编码写死在 RTL 里，就等于把这个决定钉死在了一个平台上。
用综合属性控制（AMD `FSM_ENCODING`、Synopsys `fsm_encoding`）可以一份代码两边最优。

`[SV]` 用 `enum` 更好：`typedef enum logic [1:0] {S_IDLE, S_RUN, ...} state_e;`
——波形里直接显示状态名，且把状态变量误当数用会被工具挡下。

## 5. `default` 分支与非法状态恢复

### 5.1 `default` 必须写 `[通用]` `[教材]` p.177、p.57

不写 `default`，组合次态块就有路径没赋值 → 推断出锁存器（见 `03-combinational-logic.md`）。

### 5.2 `default` 赋什么值：教材与本规范的分歧 `[通用]`

| 主张 | 理由 |
|---|---|
| **教材 p.177**：`default: next_state = 'bx;` | 把非法状态交给综合器当 don't-care 优化，**面积最小** |
| **本规范**：`default: next_state = S_IDLE;` | 一旦真的进入非法状态（单粒子翻转、电源毛刺），能自己回到安全态 |

赋 `'bx` 的代价是：综合器会把非法状态的次态优化成"任意值"，
于是**从非法状态出发可能永远回不到合法状态**，芯片就此挂死，只能靠外部复位救。
而且 `x` 在门级仿真与形式验证里会造成 X 传播，掩盖真正的问题。

**本规范默认赋确定值回安全态**。只有"纯组合译码器 + 无形式验证/门级仿真需求 + 面积极度吃紧"
三条同时成立，才允许赋 `'bx`。完整论证见 `14-disputes.md` D06。

### 5.3 状态数不是 2 的幂时，必须描述所有 2ⁿ 种状态 `[通用]` `[教材]` p.381 可综合(12)

教材原文：*"对存在无效状态的有限状态机……必须用 Verilog 明确地描述所有的 2 的 n 次幂种状态下的行为，
当然也包括无效状态。只有这样才能综合出安全可靠的状态机。"*

6 个状态用 3 bit 编码就有 2 个非法状态。`default` 回安全态正好覆盖它们。

### 5.4 安全关键场景：sparse FSM encoding `[ASIC]` `[业界]`

对安全/信息安全关键的状态机（OpenTitan 就是这么做的），进一步用**稀疏编码**：
状态码之间的汉明距离 ≥ 3，任何单 bit 翻转都不会落到另一个合法状态上，
配合检测逻辑可以直接报警。lowRISC 提供了 `prim_sparse_fsm_flop` 原语。

代价是状态位数明显增加，且必须阻止综合器重新编码（`dont_touch` / `fsm_encoding = none`）。

## 6. 异步状态机：禁止 `[通用]` `[教材]` p.180 13.3(3)、p.178

教材「综合的一般原则」第 (3) 条：
*"用 Verilog HDL 描述的异步状态机是不能综合的，因此应该避免用综合器来设计；
如果一定要设计异步状态机，则可用电路图输入的方法来设计。"*

**为什么**：异步状态机靠组合反馈保持状态，它的行为完全依赖各条路径的实际延时。
综合器会按功能等价去优化组合逻辑，优化之后延时关系全变，电路行为随之改变；
STA 也无法分析这种反馈环路。

本规范的立场：**所有状态机都必须是同步的、由单一时钟沿驱动**（SKILL.md F6、D4）。

- [ ] 状态机是同步的，只由一个时钟沿驱动
