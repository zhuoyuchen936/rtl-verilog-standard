# 01 · 命名、格式与文件组织

这一篇是全套规范里**技术含量最低、但收益最稳定**的部分。
它不影响综合出来的电路，只影响人和模型读代码的速度、以及审查时能不能一眼看出问题。

好消息是它几乎没有争议：教材 p.380「语汇代码的编写标准」8 条与
lowRISC/OpenTitan 的 style guide 在方向上高度一致。团队只需要**选一套并坚持**。

---

## 本篇速览

1. **一个文件一个模块，文件名 = 模块名**——这条能被工具自动检查（Verilator `DECLFILENAME`）。
2. 文件以 `` `default_nettype none `` 开头，末尾改回 `wire`。投入产出比最高的一条。
3. 时钟 `clk`、复位 `rst_n`，**低有效必须带 `_n`**。
4. 大小写风格全项目一致；常量全大写，信号 `lower_snake_case`。
5. 注释要写**接口契约和为什么**，不要复述代码已经说清楚的事。

---

## 一、文件与模块组织

### R-01-01 一个源文件只放一个模块 `[通用]` `[教材]` p.380 语汇(1)

原文："每一个 Verilog 源文件中只准编写一个模块，也不要把一个模块分成几部分或写在几个源文件中。"

**为什么**：版本控制的最小冲突单位是文件；一个文件一个模块时，
"谁改了这个模块"就是"谁改了这个文件"。另外几乎所有 EDA 工具的 filelist 都以文件为单位管理。

### R-01-02 文件名与模块名一致 `[通用]` `[教材]` p.380 语汇(2) `[工具]`

原文："源文件的名字应与文件内容有关，最好一致（例 ModuleName.v）。"

`[工具]` Verilator 的 `DECLFILENAME` 规则就是查这一条，`-Wall` 下会告警。
本 skill 的模板都遵守这条——`tb_template.v` 起初因为模块名叫 `tb_fsm_3seg` 被改名了。

### R-01-03 `` `default_nettype none `` `[通用]` `[业界]` lowRISC

```verilog
`default_nettype none
module foo (...);
    ...
endmodule
`default_nettype wire      // 必须改回来，否则污染后续编译的文件
```

**为什么**：不加它时，打错一个信号名会被 Verilog 默默当成一根新的 1-bit wire，
综合后是一根悬空线，而仿真里它可能是 `z` 或恰好不影响结果——这类 bug 极难查。
加上它，拼写错误当场变成编译错误。

**为什么末尾要改回 `wire`**：`` `default_nettype `` 是编译单元级的指令，
会一直生效到编译结束。如果不恢复，后面那些**没有**为此做好准备的第三方文件会突然编译失败。

### R-01-04 目录结构 `[通用]`

```
rtl/          可综合的设计代码
  common/     跨模块复用的原语（同步器、FIFO、握手）
tb/           testbench
sim/          仿真脚本与 filelist
syn/          综合脚本与约束（.sdc / .xdc）
docs/         规范与设计文档
```

filelist 用 `.f` 文件管理，不要在脚本里硬编码文件列表。详见 `12-toolchain.md`。

## 二、命名

### R-01-05 时钟与复位 `[通用]`

| 信号 | 命名 |
|---|---|
| 单时钟 | `clk` |
| 多时钟域 | `clk_axi` / `clk_core` / `clk_100m`（带上域的身份） |
| 低有效复位 | `rst_n` |
| 高有效复位 | `rst` |

**低有效必须带 `_n` 后缀**。这条不是审美问题：复位极性写反是一个既致命又极易发生的错误，
而 `_n` 后缀让它在代码里肉眼可见。

### R-01-06 一般信号 `[通用]` `[教材]` p.380 语汇(5)(6)

- 信号、模块、实例：`lower_snake_case`
- `parameter` / `localparam` / 宏：`UPPER_SNAKE_CASE`
- 教材语汇(6)："用户定义变量名应该是有意义的，而且含有一定的有关信息。
  而局部变量名（例如循环变量）可以是简单扼要的。"
- 教材语汇(5)："用户定义变量名的大小写应自始至终一致。"

### R-01-07 后缀体系（推荐，团队选定后全项目统一）`[业界]` lowRISC

| 后缀 | 含义 |
|---|---|
| `_i` / `_o` | 模块输入 / 输出 |
| `_n` | 低有效 |
| `_d` / `_q` | 触发器的输入 / 输出 |
| `_next` | 次态（状态机） |
| `_r` | 已寄存的版本 |
| `_s1` `_s2` | 同步器的第 1 / 2 级 |
| `_en` | 使能 |
| `_valid` / `_ready` | 握手信号 |

lowRISC 的完整形式是 `clk_i` / `rst_ni`（注意 `rst_ni` 里 `n` 在 `i` 前面）。
**用不用 `_i`/`_o` 是团队选择**——它让端口方向一目了然，但也让名字变长、
在层次化连线时略显啰嗦。本规范不强制，只要求**选定后全项目一致**。

### R-01-08 不写魔数 `[通用]` `[教材]` p.380 语汇(8)

原文："尽可能多地使用参数和宏定义，而不要在源代码的语句中直接使用字母、数字和字符串。"

现代补充：**优先 `localparam`，其次 `parameter`，尽量不用 `` `define ``**。
`` `define `` 是全局的，会污染整个编译单元，且不受模块作用域保护——
两个模块各自 `` `define WIDTH `` 就会打架。

```verilog
localparam [1:0] S_IDLE = 2'd0;   // 好：模块作用域
parameter integer DATA_W = 32;    // 好：可从外部配置
`define DATA_W 32                 // 差：全局污染
```

## 三、格式

### R-01-09 每行一个声明或语句 `[通用]` `[教材]` p.380 语汇(3)

### R-01-10 逐层缩进，4 空格，不用 Tab `[通用]` `[教材]` p.380 语汇(4)

Tab 在不同编辑器里宽度不同，会让对齐彻底失效。行宽建议 100 列
（lowRISC 用 100，Google 用 100，教材未规定）。

### R-01-11 端口用 ANSI 风格声明，一行一个 `[V2001]` `[SV]`

```verilog
// 推荐：ANSI 风格，方向/类型/位宽/名字都在一处
module fifo #(
    parameter integer DW = 8,
    parameter integer AW = 4
) (
    input  wire           clk,
    input  wire           rst_n,
    input  wire           wr_en,
    input  wire [DW-1:0]  wr_data,
    output wire           full
);
```

教材的模板（p.377）用的是 Verilog-1995 的非 ANSI 风格
（端口名列在模块头、方向在模块体内再声明一遍）。那是当年的写法，
Verilog-2001 起 ANSI 风格是标准，且**少写一遍就少一次不一致的机会**，本规范采用 ANSI。

### R-01-12 例化用命名端口连接 `[通用]`

```verilog
// 推荐
fifo #(.DW(8), .AW(4)) u_fifo (
    .clk     (clk),
    .rst_n   (rst_n),
    .wr_en   (wr_en),
    .wr_data (wr_data),
    .full    (fifo_full)
);

// 反例，不要抄：按位置连接。加一个端口就全线错位，且完全看不出接的是什么
fifo u_fifo (clk, rst_n, wr_en, wr_data, fifo_full);
```

也不要用 `.*` 隐式连接——它省下的几行远不值它带来的"这根线到底接到哪了"的困惑。

实例名建议加 `u_` 前缀（`u_fifo`），一眼区分实例名和模块名。

## 四、注释

### R-01-13 注释写契约和理由，不复述代码 `[通用]` `[教材]` p.380 语汇(7)

原文："通过注释对 Verilog 源代码作必要的说明，当然没有必要把 Verilog 源代码已能说明的
再注释一遍，而对接口（例如模块参数、端口、任务、函数变量）做必要的注释很重要。"

```verilog
// 没用：复述代码
cnt <= cnt + 8'd1;    // cnt 加一

// 有用：解释为什么
// 这里不复位 cnt：它是纯数据通路，valid 链已复位，cnt 在 valid 为 0 时不被使用
```

### R-01-14 模块头注释模板 `[通用]`

```verilog
// =============================================================================
// 模块名   : <name>
// 功能     : <一句话>
// 时钟域   : clk（单一时钟域）／或列出多个域
// 复位     : rst_n，低有效，异步复位 / 同步释放
// 依赖     : <被例化的子模块>
// -----------------------------------------------------------------------------
// 设计要点 :
//   - <关键的时序/吞吐/背压约定>
//   - <外部必须遵守的接口协议>
// CDC      : <有无跨时钟域路径；若有，用的是哪种同步结构>
// =============================================================================
```

「时钟域」「复位」「CDC」三项是**强制**的——它们回答的正是审查者第一时间要问的问题。

> ⚠️ **一个实测到的坑**：注释的第一个词如果是 `verilator`，会被当成编译指示，
> 报 `Unknown verilator comment`。写"用 verilator 跑一下"这种说明时，
> 在前面加个字（如 `$ ` 或 `注：`）避开。

## 本篇检查清单

- [ ] 一个文件一个模块，文件名 == 模块名
- [ ] 文件以 `` `default_nettype none `` 开头、`` `default_nettype wire `` 结尾
- [ ] 时钟叫 `clk`，复位叫 `rst_n`（低有效带 `_n`）
- [ ] 常量全大写，信号 `lower_snake_case`，全项目大小写风格一致
- [ ] 后缀体系全项目统一（选了就别混用）
- [ ] 没有魔数；常量用 `localparam` / `parameter`，没有滥用 `` `define ``
- [ ] 4 空格缩进，无 Tab，行宽不超过约定值
- [ ] 端口 ANSI 风格、一行一个
- [ ] 例化用命名端口连接，实例名带 `u_` 前缀
- [ ] 模块头注释齐全，特别是时钟域 / 复位方式 / CDC 三项
- [ ] `verilator --lint-only -Wall` 无 `DECLFILENAME` / `IMPLICIT` 告警
